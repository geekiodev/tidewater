# Build log

Running log of what the build agent did for each prompt in the prompt pack, including what was skipped or simplified and why.

## Environment facts that affect the whole build

- **No Docker images.** The Docker daemon starts, but pulls from Docker Hub / ECR are refused by the network proxy, so `npx supabase start` (which needs Docker images) **cannot run here**. Nothing in this build has been run against the real Supabase stack (GoTrue auth, PostgREST, Supabase's own Postgres image).
- **Real Postgres is available.** The local PostgreSQL 16 cluster was started and is used to apply the migrations and run the database tests. Supabase's `auth` schema, roles and `auth.uid()` don't exist in plain Postgres, so tests load a small shim (`tests/db/supabase-shim.sql`) that recreates just those pieces. Supabase local uses Postgres 17; tests here ran on 16.
- **No credentials.** No Stripe, Supabase or Anthropic keys exist here. Only dummy values appear, in `.env.example`. Nothing has been called against Stripe or Anthropic.
- **No docs access.** The Anthropic docs couldn't be fetched, so the model ID is an environment variable (`ANTHROPIC_MODEL`, default `claude-haiku-4-5`). Confirm it against current docs before launch.

## Prompt 0: Context

**Built**
- Next.js 16.4.2 app (App Router, TypeScript, `src/` layout) scaffolded with `create-next-app`; Supabase CLI project initialised (`supabase/config.toml`).
- Dependencies: `@supabase/supabase-js`, `@supabase/ssr`, `stripe`, `@anthropic-ai/sdk`, `zod`, `server-only`; dev: `vitest`, `pg`, `supabase` CLI.
- `src/lib/env.ts`: every setting read from environment variables, validated with zod, grouped and validated lazily so the app builds without secrets. Stripe keys must be `sk_test_` (test mode only).
- `.env.example` with dummy values only; `.gitignore` ignores all `.env*` except `.env.example`.
- Landing page; template assets and the Google Fonts import removed (the build fetches fonts from Google, which isn't reachable here, and it adds a third-party origin to the CSP).
- Supabase auth config hardened: 12-char passwords with mixed case and digits, email confirmation on, secure password change on, redirect URLs limited to the local callback.
- npm scripts: `typecheck` (runs `next typegen` first because `next-env.d.ts` is generated and git-ignored), `lint` (zero warnings allowed), `test`.

**Decisions / simplifications**
- `cacheComponents` was on in the Next 16 template; turned **off**. Every page is per-user, and the nonce-based CSP (Prompt 3) needs dynamic rendering anyway. Less to get wrong in a first version.
- `@types/node` set to `^22` to match the Node 22 runtime (the template's `^20` conflicted with vitest 5's peer range).
- `AGENTS.md` generated by Next.js is kept (it only tells agents to read the bundled Next docs; no secrets).

**Known issues**
- `npm audit` reports 5 high-severity advisories, all in the `braces`/`micromatch` chain under `eslint-config-next` (dev-only lint tooling, not shipped). The only "fix" npm offers is downgrading `eslint-config-next` to 14.x, which would break linting on Next 16. Left as is; revisit when upstream updates.
